## Project

The public landing page of The Fisher Slopworks Co, served at
[slopworks.org](https://slopworks.org) by GitHub Pages. One static page in plain
HTML, CSS and JavaScript: no build step, no package manager, no dependencies.
See `README.md` for what it is; this file covers how to work on it.

### Commands

```bash
just serve      # preview on http://localhost:8000 (python3 -m http.server)
just og         # redraw assets/og.png from assets/og.svg (rsvg-convert + ImageMagick)
just lint       # reuse lint: the repo's whole check gate, needs `reuse` (or `uvx reuse lint`)
```

### Layout

- `index.html`: the whole page, including the project catalog (one card per
  project, plus the filter chips and their counts).
- `assets/`: `styles.css`, `main.js` (catalog filter and the deferred d10
  embed), the favicon, the avatar and the Open Graph card (`og.svg` is the
  source, `og.png` is generated by `just og`).
- `llms.txt`, `robots.txt`, `sitemap.xml`: files for crawlers and agents.
  `llms.txt` repeats the catalog in Markdown.
- `CNAME` (the custom domain) and `.nojekyll`.
- `.github/workflows/deploy.yml` uploads the repository root as the Pages
  artifact on every push to main. Everything at the root except dotfiles,
  `.git` and `.github` is published.

### Conventions

- **SPDX header on every new file** that can hold a comment (`<!-- -->` in
  HTML, `/* */` in CSS, `//` in JS, `#` elsewhere). `REUSE.toml` covers the
  rest under the same AGPL-3.0-or-later grant.
- **The catalog lives in two places:** a project added to or removed from
  `index.html` also changes the filter counts there and its line in
  `llms.txt`.
- After editing `assets/og.svg`, run `just og` and commit both files.

### Definition of done

- **Issues and pull requests are written in English** — title and body, whatever language the task was discussed in.
- **Never commit to main.** Every task starts on a fresh branch off `origin/main`, named `<type>/<short-task>` — `fix/`, `feat/`, `refactor/`, `chore/`.
- **One task = one branch = one PR.** Past ~300 changed lines, split it into several PRs. `.github/workflows/pr-size.yml` labels every PR `size:XS`…`size:XXL`; **`size:XL` or `size:XXL` means split the PR**, not "explain why it is large".
- **PR title is the squash commit subject:** conventional commit with a scope, enforced by `.github/workflows/pr-title.yml`.
  - Type: `feat` `fix` `refactor` `chore` `docs` `test` `ci` `perf` `revert`.
  - Scope (required): a part of the site — `page` (`index.html`), `assets` (`assets/`), `catalog` (the project catalog in `index.html` and `llms.txt`), `seo` (`llms.txt`, `robots.txt`, `sitemap.xml`, meta tags) — or `deps` `github`. A new area means adding it to the `scopes:` list in that workflow.
  - Subject: lowercase start, imperative, no trailing period.
  - The body describes this PR alone, following the PR template.
- **No AI attribution.** No `Assisted-by:` / `Co-Authored-By: <LLM>` trailers, no agent as commit author or committer, and no "Generated with/by …" lines or agent-platform links in PR bodies. The PR body becomes the squash commit body, so the PR title workflow checks the title, the body and every commit of the PR.
- **Before opening:** `just lint` green and the page checked with `just serve`, then open the PR and report its URL.
- **Never merge locally.** Merging happens on GitHub, squash only.
